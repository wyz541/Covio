# ADR-0029：固定工作台外壳高度

- Status：accepted
- Kind：architecture
- Date：2026-11-03
- Supersedes：none
- Implements：#583
- 相关：[挂帘工作台需求规格](../design/workbench-architecture.md)

## 背景

工作台当前按页面内容计算窗口高度。
页签切换时，SwiftUI 内容高度进入切页动画。
AppKit 窗口又在另一条路径立即改高。
两条时间线不一致，导致整个工作台抖动。

监控页主体高 764 点。
剪切板页主体高 482 点。
两页切换会改变 282 点窗口高度。

## 决策

1. 每块屏幕只计算一次工作台外壳高度。
2. 首选内容高度是 880 点，并限制在屏幕高度减 120 点内。
3. 页签切换和编辑模式切换不改变 `NSPanel` 矩形。
4. 页面内容在固定视口内滚动。
5. 屏幕、菜单栏或显示器配置变化时，重新计算外壳高度。
6. `ScreenGeometry` 是外壳尺寸的唯一计算来源。

## 后果

### 正面

- 页签切换不再驱动窗口缩放。
- SwiftUI 和 AppKit 不再同时修改高度。
- 顶栏、导航玻璃和窗口位置保持稳定。
- 页面切换的布局计算范围更小。

### 负面

- 较短的页面会保留额外空白。
- 较小屏幕上的页面需要内部滚动。
- 设计合同新增一枚固定外壳高度令牌。

### 风险

- 固定高度可能遮挡低分辨率屏幕的底部内容。
- 页面内容使用统一滚动容器，避免嵌套滚动争抢手势。
- 真机验收覆盖刘海屏、非刘海屏和最小窗口高度。

## 备选方案

### 备选 1：继续按页面内容改变高度

保留现有自适应高度。
窗口与 SwiftUI 使用同一个动画事务。

未采用的原因是实现复杂，而且任意页面更新仍可能触发窗口重排。

### 备选 2：所有屏幕使用同一个绝对高度

所有屏幕都使用 880 点。

未采用的原因是小屏幕会越界，无法满足最大高度限制。

### 备选 3：固定全局高度

所有页面在所有屏幕上使用同一个高度。

未采用的原因是屏幕可用高度不同，小屏幕会裁掉内容。
