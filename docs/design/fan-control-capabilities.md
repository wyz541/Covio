# 风扇控制能力补齐

本文定义 #330 风扇能力补齐的交互与组件选择。
本文服务于 #331 预览评审和后续实现 sub-issue。

## 1. 结论

风扇曲线使用 Apple `Swift Charts`。
不手绘曲线 Canvas。
Popover 使用原生 SwiftUI 控件和固定头部。
系统自动模式交还 macOS 控制。
曲线是显式控制模式，不等同于系统自动模式。

## 2. 结构

| 区域 | 内容 |
| --- | --- |
| 固定头部 | 每台风扇的当前使用率、RPM 和进度条 |
| 滚动内容 | 策略选择、共享曲线、当前风量、控制传感器 |
| 折叠区 | 精确调节、高级设置、维护与导航 |
| 固定操作 | 交回 macOS |

Popover 宽 `420` 点。
系统策略高 `300` 点。
曲线策略高 `600` 点。
头部固定。
内容在头部下方滚动。
卡片尺寸和 Monitor 网格不随内容变化。

popover 外壳使用系统 regular Liquid Glass。
控制面板使用 `.clear` Liquid Glass。
策略、恢复、节点和增删按钮使用原生 Liquid Glass 控件。
选中玻璃通过 `glassEffectID` 与 matchedGeometry 在相邻位置之间形变。
系统开启降低透明度或增强对比度时，内容面板退回不透明表面。

## 3. Swift Charts

曲线必须使用 `Chart`。

| 元素 | 组件 |
| --- | --- |
| 曲线 | `LineMark` |
| 控制点 | `PointMark` |
| 坐标轴 | `AxisMarks` |
| 拖动命中 | `chartOverlay` + `ChartProxy` |
| 数值编辑 | 原生 `Slider` |

拖动控制点后更新温度和转速。
控制点按温度排序。
每风扇转速限制在 `F%dMn` 到 `F%dMx`。

## 4. 曲线模式

「系统」策略表示系统自动控制。
系统自动模式不持有风扇，不写 `F%dTg`。

- 策略为系统、安静、编译、持续和自定义。
- 非系统策略共用一条温度到风量百分比的曲线。
- 两台风扇使用同一条百分比曲线。
- 百分比按每台风扇自己的最高转速换算为 RPM。
- 曲线节点支持拖动、增加、删除和精确滑杆编辑。
- 图上同时显示预设目标风量和当前实际风量。
- 内置预设允许覆盖并恢复默认控制点。
- 自定义策略保存用户控制点。
- 两点直线是多点曲线的特例。

## 5. 手动模式

- 每个风扇使用独立原生滑杆。
- 每台风扇独立选择自动或手动。
- 自动模式释放该风扇。
- 手动模式只显示并控制该风扇。
- 滑杆变化等待 `300 ms` 后提交。
- 多风扇设备提供同步开关。
- 同步开关默认关闭。
- 同步开启后，滑杆按转速百分比映射到每台风扇的 `Mn` 到 `Mx`。
- 同步开启后，自动和手动模式变化也同步。
- 关闭同步后，每个风扇恢复独立控制。
- 单风扇提供全速动作。
- 全局提供全部风扇全速动作。
- 手动值始终限制在硬件范围。

## 6. 夜间模式

夜间模式包含启用开关、开始时间、结束时间和预设。
时间窗支持跨午夜。
生效时显示文字和状态图标。

## 7. 通知

| 通知 | 触发条件 |
| --- | --- |
| 高温 | 控制温度达到用户阈值 |
| 风扇故障 | 目标转速大于 0，实际转速为 0 |

通知有冷却时间。
关闭通知后不发送。

## 8. 传感器

传感器列表显示名称、键名和当前温度。
列表支持按名称或键名筛选。
至少保留一个控制传感器。
完整名称库包含 64 个显式键名。
未知键显示原始四字符键名。

## 9. 无障碍

- 曲线使用 `LineMark` 和 `PointMark` 的原生可访问性。
- 图表提供汇总可访问性值。
- 拖动不是唯一编辑方式。每个控制点同时提供温度和转速滑杆。
- 状态同时显示图标、文字和颜色。
- 所有可点击控件使用原生按钮、开关、分段控件和滑杆。
- 减少动态效果时，滚动定位不使用动画。
