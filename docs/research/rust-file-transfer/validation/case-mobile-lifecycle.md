## 4. 验证步骤

### V17：iOS 后台暂停

前置条件：iOS 与 macOS 已配对。传输正在进行。测试文件至少 `1 GiB`。

请求模板：

```text
transfer.start(task_id)
ios.enter_background()
```

预期结果：

- 核心停止发起新分块。
- 已写入分块完成同步。
- 检查点写入持久记录。
- 任务状态变为 `background_deferred`。
- 任务不显示为失败。
- 暂存文件保留。

实际结果字段：后台前确认字节、后台后确认字节、任务状态、错误码、结果。

### V18：iOS 前台验活和恢复

前置条件：V17 已完成。网络仍然可用。

请求模板：

```text
ios.enter_foreground()
transfer.resume(task_id)
```

预期结果：

- 应用先执行连接验活。
- 旧 socket 无效时立即重连。
- 对端公钥和清单摘要一致。
- 从持久检查点继续。
- 不从头重传已确认分块。
- 最终文件校验通过。

实际结果字段：前台时间、验活结果、重连次数、恢复字节、错误码、结果。

### V19：iOS 后台收到新请求

前置条件：iOS 应用在后台。macOS 发送新文件请求。

请求模板：

```text
transfer.offer(manifest)
ios.enter_foreground()
```

预期结果：

- 后台不自动接受请求。
- 请求在保留期限内保持待确认。
- 用户打开应用后看到文件摘要。
- 用户必须明确接受。
- 用户拒绝后返回 `offer_rejected`。
- 未接受前没有文件内容传输。

实际结果字段：请求到达时间、待确认状态、用户选择、数据流状态、结果。

### V20：iOS 取消和重启恢复

前置条件：传输正在进行。执行人可以取消或强制结束应用。

请求模板：

```text
transfer.cancel(task_id, "receiver")
app.terminate()
app.launch()
transfer.status(task_id)
```

预期结果：

- 取消状态持久化。
- 重启后任务不自动恢复为传输中。
- 已完成文件保留。
- 暂存文件按 `24 h` 策略处理。
- 不出现未完成最终文件。
- 错误码为 `cancelled_by_receiver`。

实际结果字段：取消时间、重启后状态、暂存文件状态、错误码、结果。
