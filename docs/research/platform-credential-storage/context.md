# 跨平台凭据存储的问题边界

凭据合同必须按安全能力分层。平台名称不能代表相同安全等级。

> 本文件定义研究问题、范围、角色、系统模型、状态矩阵、场景和成功标准。

## 1. 问题类别与研究问题

### 1.1 问题类别

本文处理一类跨平台秘密数据保护问题。
应用需要在多个操作系统保存少量长期秘密。
操作系统提供不同的安全存储接口。
接口的访问控制、备份语义和设备绑定不相同。
产品需要一套稳定合同。
合同不能把这些差异写成同一种保证。

### 1.2 研究问题

Covio 如何在 macOS、Windows 和 iOS 上保存设备身份、二维码配对记录和传输密钥？
Android 加入后，合同如何接入 Android Keystore？
平台原生安全存储能否与 Rust 统一 facade 组合？
哪些能力必须分开表达？
哪些请求必须失败关闭？

研究问题拆成五个子问题。

1. 三个首发平台的原生安全存储提供哪些能力？
2. 三个首发平台的访问控制、备份和恢复语义有何差异？
3. Rust facade 如何统一类型、生命周期、错误和审计？
4. 哪些秘密放在原生存储，哪些记录放在 Rust 加密仓库？
5. 如何预留 Android Keystore，而不假设访问控制一致？

### 1.3 问题定义

凭据是本产品管理的秘密数据。
凭据示例是配对预共享密钥、传输根密钥和提供方 API 密钥。
根密钥是加密记录的主密钥。
记录是根密钥加密后的秘密载荷和元数据。

统一 facade 是 Rust 提供的调用入口。`facade` 在本主题中只表示这个入口。
平台适配器是 facade 后面的原生实现。
平台适配器调用 Keychain、Credential Manager 或 Keystore。

问题不是“是否有安全存储”。
问题是如何表达真实能力。
问题也是如何在不丢失安全语义时迁移。

### 1.4 触发条件

满足任一条件时，本文适用。

1. 首次创建本地凭据仓库。
2. 用户完成二维码配对。
3. 后台接收任务需要读取传输凭据。
4. 用户保存提供方 API 密钥。
5. 应用升级数据格式。
6. 用户撤销设备。
7. 系统锁定、认证撤销或密钥失效。
8. 用户恢复备份或迁移到新设备。
9. Android 进入产品范围。

### 1.5 问题分类

| 类别 | 表现 | 主要因素 | 推荐路径 |
| --- | --- | --- | --- |
| 原生能力差异 | 同一请求在不同平台得到不同保护 | 平台接口和 ACL 不同 | 先查询能力，再选择策略 |
| 设备绑定 | 新设备可恢复旧秘密 | 备份和同步语义不同 | 使用设备绑定策略 |
| 用户认证 | 后台任务被认证提示阻断 | 用户在场策略不同 | 分离后台密钥和审批密钥 |
| 硬件保护 | 软件密钥被误称为硬件密钥 | 硬件支持不稳定 | 查询并报告真实保护等级 |
| 备份恢复 | 恢复后记录不可解密 | 根密钥不可迁移 | 失败关闭并要求重新配对 |
| 迁移 | 旧适配器无法读取新记录 | 后端和格式变化 | 两阶段迁移 |
| 错误语义 | UI 无法区分取消、锁定和失效 | 原生错误不统一 | 稳定错误码和用户动作 |
| 日志泄露 | 秘密进入日志或崩溃报告 | 边界复制和调试输出 | 脱敏和零化 |

### 1.6 状态矩阵

| 状态 | 首次创建 | 读取 | 写入 | 删除 | 轮换 | 恢复 |
| --- | --- | --- | --- | --- | --- | --- |
| 已解锁且已认证 | 可用 | 可用 | 可用 | 可用 | 可用 | 可用 |
| 设备已锁定 | `按平台` | 等待解锁 | 等待解锁 | 等待解锁 | 等待解锁 | 等待解锁 |
| 需要用户认证 | 需要认证 | 需要认证 | `按策略` | `按策略` | 需要认证 | 需要认证 |
| 用户取消认证 | 未创建 | 保持锁定 | 保持锁定 | 保持锁定 | 保持锁定 | 保持锁定 |
| 认证失败 | 未创建 | 保持锁定 | 保持锁定 | 保持锁定 | 保持锁定 | 保持锁定 |
| 原生密钥失效 | 重建仓库 | 失败关闭 | 失败关闭 | 允许清除 | 重建仓库 | 重新配对 |
| 原生存储不可用 | 失败关闭 | 失败关闭 | 失败关闭 | 尽力清除 | 失败关闭 | 失败关闭 |
| 记录校验失败 | 不适用 | 隔离记录 | 拒绝覆盖 | 允许清除 | 隔离记录 | 重新配对 |
| 新设备恢复备份 | 新建 | 无旧根密钥 | 可写新记录 | 可用 | 可用 | 重新配对 |

 `按平台` 表示结果由平台能力决定。适配器必须返回有效能力。
 `按策略` 表示结果由产品选择决定。当前选择写在 [solution.md](solution.md) 第 5 节。

### 1.7 解决路径

推荐路径分两层。
原生安全存储只保护一个小根密钥。
Rust 仓库加密并解释业务记录。
Rust facade 检查策略和平台能力。
不满足策略时，操作返回稳定错误。
产品不能静默降低安全等级。

## 4. 系统模型

### 4.1 组件

| 组件 | 职责 | 所在层 |
| --- | --- | --- |
| 凭据 facade | 校验请求、查询能力、执行策略和映射错误 | Rust |
| 加密记录仓库 | 保存密文、元数据和非秘密索引 | Rust |
| 根密钥适配器 | 保存、读取、轮换和删除根密钥 | 平台层 |
| 设备密钥适配器 | 使用平台非导出密钥完成签名或密钥协商 | 平台层 |
| 认证桥 | 显示平台认证提示并返回结构化结果 | UI 或平台层 |
| 迁移器 | 读取旧格式并写入新格式 | Rust 与平台层 |
| 审计记录器 | 只记录非秘密操作元数据 | Rust |

### 4.2 参与者

| 参与者 | 说明 |
| --- | --- |
| 用户 | 创建仓库、完成配对、批准敏感操作 |
| Rust core | 决定秘密用途和记录生命周期 |
| 平台适配器 | 执行原生安全存储操作 |
| 操作系统 | 执行 ACL、设备锁定、认证和密钥失效 |
| 后台任务 | 需要传输密钥，但不控制 UI |
| 对端设备 | 通过二维码配对并持有自己的设备秘密 |

### 4.3 生命周期

```text
创建根密钥 -> 验证往返 -> 创建仓库 -> 建立配对记录 -> 正常读写
     -> 轮换或迁移 -> 验证新根密钥 -> 删除旧根密钥
     -> 撤销或重置 -> 清除本地秘密 -> 重新配对
```


### 4.4 状态变化

| 阶段 | 正常 | 异常 |
| --- | --- | --- |
| 创建 | 原生存储返回根密钥句柄 | 原生存储不可用，停止创建 |
| 读取 | 认证通过并解密记录 | 锁定、取消或校验失败 |
| 写入 | 新记录落盘并校验 | 空间不足或版本冲突 |
| 轮换 | 新根密钥验证后切换 | 验证失败时保留旧根密钥 |
| 迁移 | 旧记录全部回读成功 | 部分失败时停止切换 |
| 撤销 | 删除对端记录并轮换组密钥 | 删除失败时保留撤销标记 |
| 恢复 | 同设备可打开旧根密钥 | 新设备无根密钥，要求重新配对 |

## 5. 场景定义

### 5.1 二维码首次配对

两台设备使用二维码建立信任。
二维码携带公开身份信息和临时会话信息。
二维码不能携带长期根密钥。
双方确认后保存配对记录。
配对记录必须设备绑定。

### 5.2 移动端后台接收

iOS 或 Android 应用退到后台。
接收任务可能继续运行。
接收任务需要传输密钥。
平台锁定状态可能禁止读取密钥。
合同必须区分继续、暂停和失败。

### 5.3 提供方密钥保存

用户输入第三方提供方 API 密钥。
UI 可以写入密钥。
UI 默认不能读回密钥。
Rust core 只在调用提供方时使用密钥。

### 5.4 设备撤销

用户撤销一台已配对设备。
本地删除该设备的信任记录。
本地轮换受该设备影响的组密钥。
远端设备不能继续使用旧会话。

### 5.5 备份恢复到新设备

用户从备份恢复应用数据。
密文可能回到新设备。
根密钥不应迁移到新设备。
解密的请求必须失败关闭。
产品应引导用户重新配对。

### 5.6 旧实现迁移

当前实现使用按 key 保存的 secret 接口。
新实现使用根密钥和加密记录。
迁移必须保留旧值或完整回滚。
迁移不能在旧值删除前报告成功。

## 6. 成功标准

1. 合同区分设备绑定、硬件保护、用户在场和备份范围。
2. facade 不假设三个平台具有相同 ACL。
3. 不支持的请求返回 `credential_policy_unsupported`。
4. 根密钥不通过普通 JSON、日志或 UI snapshot 传输。
5. UI 不能读取通用秘密。
6. 后台接收密钥与审批密钥可以分开配置。
7. 新设备恢复不能静默生成旧仓库根密钥。
8. 密钥失效返回 `credential_key_invalidated`。
9. 记录损坏返回 `credential_integrity_failed`。
10. 迁移失败保留旧数据。
11. 每条错误有可重试标记和用户动作。
12. 每个平台有独立验证案例。
13. 未执行的验证标记为 `尚未执行`。
14. 事实、推论、假设和缺口有明确标记。

## 7. 假设

1. 首发版本不提供账号体系。
2. 首发版本不提供云端密钥备份。
3. 配对和传输需要设备绑定秘密。
4. 后台接收可以在平台允许时继续。
5. Windows Compose 宿主运行在当前用户会话。
6. Android 后续平台仍使用 Compose Multiplatform 和 Rust core。
7. 用户接受新设备恢复后重新配对。
8. 正式发布不把安全合同当作已认证合规声明。

## 8. 已知边界

Apple 数据保护 Keychain 只适用于有用户上下文的主应用或扩展。
Windows Credential Manager 只访问当前令牌的凭据集。
Android Keystore 保存密钥，不直接保存任意大块秘密。
三个平台都要求把认证提示放到 UI 线程之外或平台指定线程。
合同必须表达这些边界。
